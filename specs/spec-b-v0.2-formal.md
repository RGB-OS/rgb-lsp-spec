# Specification B v0.2 — Formal Model and Proofs

**Status:** Formal companion to `spec-b-v0.2.md` (the *Spec*), same version and audit scope
**Purpose:** State the protocol as a mathematical object and prove, from an explicit axiom set:

1. **Achievability** — every protocol operation and every claimed guarantee is *realizable*: epochs can always be constructed (Proposition P1), all cooperative operations terminate (Proposition P2), and unilateral exit succeeds within a computed bound (Theorem T2).
2. **Absence of unintended behaviors** — the reachable outcome space is *exactly* the intended set: every satoshi and every USDT unit committed to an epoch terminally resolves into one of six enumerated dispositions, and no execution — adversarial or otherwise — produces a residual claim, a stuck state, or an outcome outside that set (Lemma L1, Theorem T6). This discharges the requirement that the design contain no unexpected or irrelevant reachable states.

Every axiom is mapped to a Spec assumption (A1–A7); every theorem is mapped to a Spec guarantee (G1–G5). Anything the proofs do *not* cover is listed in §9.

## 1. Ledger model

**Definition 1.1 (Transactions and outputs).** A *transaction* is a tuple `t = (in(t), out(t), lt(t), seq_t)` where `in(t)` is a finite sequence of *outpoints* (pairs `(txid, index)`), `out(t)` a finite sequence of *outputs*, `lt(t) ∈ ℕ` its locktime, and `seq_t : in(t) → ℕ ∪ {⊤}` its per-input relative-timelock field (⊤ = disabled). An *output* is `o = (v(o), a(o), cond(o))`: a satoshi value, an asset annotation (§3), and a *spending condition*. `txid(t)` is a collision-resistant hash of `t` excluding witness data; since every protocol transaction spends only SegWit outputs, `txid(t)` is fixed by `t`'s non-witness content (used tacitly whenever a transaction is signed before its parent is broadcast).

**Definition 1.2 (Spending conditions).** Conditions are generated by:

```text
cond ::= Key(P)                       single key P
       | Agg(S)                       MuSig2 aggregate of the key set S
       | Rev(P, P')                   P, or P' with the revocation secret
       | CSV(δ, cond)                 cond, spendable only ≥ δ blocks after this output confirms
       | CLTV(h, cond)                cond, spendable only at height ≥ h
       | cond ∨ cond                  taproot key path / script path alternative
```

**Definition 1.3 (Chains and validity).** A *chain state* at height `h` is a sequence of blocks; `conf(t)` denotes the height at which `t` is included, `utxo(h)` the unspent-output set at height `h`. A block at height `h` may include `t` iff every `p ∈ in(t)` is in `utxo(h−1)`; `lt(t) ≤ h`; for every input `p` with `seq_t(p) = δ ≠ ⊤`, `h ≥ conf(parent(p)) + δ`; and each input carries a *witness* satisfying its output's condition:

- `Key(P)`: a signature valid under `P` on `sighash(t)`;
- `Agg(S)`: a BIP-327 aggregate signature under `S` on `sighash(t)`;
- `Rev(P, P')`: a signature under `P`, or a signature under `P'` together with the revocation secret;
- `CSV(δ, c)`: witness for `c`, and the input's `seq` encodes `≥ δ` (consensus checks the height condition);
- `CLTV(h', c)`: witness for `c`, and `lt(t) ≥ h'`;
- `c₁ ∨ c₂`: witness for `c₁` or for `c₂`.

`sighash(t)` commits to `t` in full (all-input signing); hence a signature on `t` authorizes exactly `t` and no other transaction. Two transactions *conflict* if their input sets intersect; a chain never contains both.

**Axiom AX-FIN (finality; Spec A1).** There is `k ∈ ℕ` such that any transaction `k`-deep in the chain is permanent: no execution removes it. Consequently `utxo` evolves consistently and no outpoint is ever spent twice.

**Axiom AX-CONF (confirmation liveness; Spec A1+A6).** There are `T_conf ∈ ℕ` and a fee level `f*` such that: any standard transaction which (itself or via a CPFP child on an anchor spendable by its broadcaster) pays `≥ f*` and whose inputs are in the UTXO set and whose timelocks are satisfied, if (re-)broadcast by any party, confirms within `T_conf` blocks. The adversary cannot censor beyond this bound.

*Remark.* AX-CONF is the formalization of the fee-envelope assumption; Spec [B-47] requires deployments to justify `(f*, T_conf)` empirically and size `R_min` accordingly.

## 2. Authorization and signature axioms

Let `H ⊆ Parties` be the honest parties. Each party `i` has key `P_i`; the operator has `P_O`.

**Axiom AX-SIG (insider-secure aggregation; Spec A5).** For any key set `S` and message `m`: a valid signature under `Agg(S)` on `m` exists in any execution only if **every** `i ∈ S ∩ H` executed the BIP-327 signing protocol for `(S, m)`. Likewise a valid signature under `Key(P_i)`, `i ∈ H`, exists only if `i` signed `m`. (Standard EUF-CMA for Schnorr; MuSig2 insider security against `|S|−1` corruptions, under the BIP-327 nonce discipline mandated by Spec [B-13].)

**Corollary 2.1 (Message closure).** For honest `i`, define `Sig_i` = the set of messages `i` has signed (alone or in aggregate sessions). Then every valid signature "involving" `i` — under `Key(P_i)` or under `Agg(S)` with `i ∈ S` — is a signature on some `m ∈ Sig_i`. ∎

Corollary 2.1 turns protocol-level signing discipline (§5) into a ledger-level exclusion principle: whatever honest parties never signed *cannot be spent that way*, no matter what the adversary does.

## 3. Asset (RGB) model

**Definition 3.1 (Allocations and transitions).** Fix the canonical contract with total issued supply `Q ∈ ℕ`. An *allocation state* is a partial map `alloc : Outpoints ⇀ ℕ` (USDT atomic units bound to single-use seals = outpoints). A *transition* `τ` consumes allocations on the inputs of a witness transaction `w(τ)` and creates allocations on outpoints, subject to:

**Axiom AX-RGB (validation soundness + conservation; Spec A2).** A party validating a consignment (a genesis-rooted chain of transitions) accepts iff every transition conserves value (`Σ inputs = Σ outputs`), every seal is closed by exactly the committed witness transaction, and the chain roots in genesis. Ownership: a validated allocation on an outpoint whose condition only party `i` can satisfy is spendable (as USDT) only by `i`.

**Axiom AX-VS (virtual seals; Spec A3 / dependency D-VS).** AX-RGB extends to transitions whose witness transactions are pre-signed and unconfirmed at validation time: the resulting allocation is *conditionally valid*, and becomes valid outright when the exact txid chain confirms (VS-1); no party can bind a different transition to the same chain after signing, because the tapret commitment is inside the signed transaction (VS-2); the consignment for a path can be built at signing time (VS-3) and covers leaf-channel state transitions (VS-4).

*AX-VS is the protocol's declared R&D dependency (Spec R-1). Every result below that touches USDT (not the BTC skeleton) is conditional on it; §9 tracks this precisely.*

**Lemma 3.2 (Seal injectivity).** No two validated transitions consume the same allocation. *Proof.* A transition's seal closure requires its witness transaction to spend the seal's outpoint (AX-RGB/AX-VS); two such transitions would need two confirmed transactions spending one outpoint, contradicting AX-FIN. ∎

## 4. Protocol objects

Fix parameters `Π = (r, N_max, W_exp, Δ_leaf, Δ_rev, k, T_conf, R_min, btc_leaf, M, B)` satisfying the Spec §19 constraints, in particular

```text
(M-bound)    M ≥ depth·T_conf + Δ_leaf + Δ_rev + 2·T_conf + B,   B ≥ k,
             where depth = ⌈log_r |S|⌉ for the cohort in question.
```

**Definition 4.1 (Epoch).** An *epoch* is a tuple `Ep = (N, S, E, T, ℓ, a, H_exp)` where:

- `S ⊆ Users`, `0 < |S| ≤ N_max` — the cohort;
- `E` — the epoch transaction; `O(E)` its cohort output, `conn_i(E)` the connector output for each refreshing `i ∈ S`;
- `T` — a finite tree whose root spends `O(E)`, each node transaction spending one parent output and creating ≤ `r` child outputs plus an anchor; leaves `{L_i}_{i∈S}`;
- `ℓ : S → ℕ` — leaf allocations, `ℓ(i) ≥ R_min`;
- `a = Σ_{i∈S} ℓ(i)` — the cohort allocation, carried by `E`'s root transition onto `O(E)`'s seal;
- `H_exp` — the uniform expiry height.

**Definition 4.2 (Well-formedness `WF(Ep)`).** All of:

1. **(Conditions.)** `cond(O(E)) = Agg(S ∪ {O}) ∨ CLTV(H_exp, Key(P_O))`; for each tree node `j` with participant set `S_j`, `cond(o_j) = Agg(S_j ∪ {O}) ∨ CLTV(H_exp, Key(P_O))`; for each leaf, `cond(L_i) = Agg({i, O}) ∨ CLTV(H_exp, Key(P_O))`; `cond(conn_i) = Key(P_O)`.
2. **(Ancestry.)** For every `i ∈ S` and every tree node `j` on the root-to-`L_i` path, `i ∈ S_j`.
3. **(Tree signatures.)** For every tree transaction `x`, a valid `Agg(S_parent(x) ∪ {O})` signature on `x` exists.
4. **(Delays.)** Every pre-signed spend of `L_i` of *commitment* type (Def. 4.3) has `seq = Δ_leaf` on its leaf input; tree transactions and forfeits have `seq = ⊤`.
5. **(RGB.)** The root transition allocates exactly `a` to `O(E)`'s seal; tree transitions conserve down to `ℓ(i)` on each `L_i` (per AX-VS); all consignments validate.
6. **(Anchors, values.)** Every pre-signed transaction carries an anchor spendable by the party needing its confirmation; `v(L_i) = btc_leaf`; all outputs standard.

`WF` is exactly the conjunction checked by ceremony checks V1–V12 (Spec §8.3); an honest client signs only within a `WF` epoch (§5).

**Definition 4.3 (Leaf channel).** For epoch `Ep` and `i ∈ S`: leaf-channel *states* are `σ = (n, u, ω)` with `u + ω = ℓ(i)`, `n ∈ ℕ` strictly increasing. For each state and each party `p ∈ {i, O}` there is a pre-signed *commitment transaction* `C_p(σ)` spending `L_i` (input `seq = Δ_leaf`) with outputs:

```text
to_p:      (CSV(Δ_rev, Key(P_p))) ∨ Rev-path for the counterparty     [USDT: p's amount]
to_other:  Key(P_other) (CSV 1)                                        [USDT: other's amount]
anchor
```

A state is *revoked* once both parties hold each other's revocation secrets for it; `latest_i` denotes the highest non-revoked state. `R_settled(i) := u(latest_i)`.

**Definition 4.4 (Forfeit).** For a refresh of `i` from `Ep_N` into `Ep_{N+1}`: `fft_i` spends `L_i^N` (via `Agg({i,O})`, `seq = ⊤`) and `conn_i(E_{N+1})` (via `Key(P_O)`), paying all value and the full `ℓ_N(i)` allocation to the operator.

## 5. Executions, strategies, and the honest-signing discipline

**Definition 5.1 (Execution).** An *execution* is an interleaving of: chain events (blocks, per §1), message events, and signing events, scheduled by the adversary subject to AX-FIN/AX-CONF. The adversary controls all parties outside `H`, all message delivery, and transaction (non-)relay within AX-CONF's bound.

**Definition 5.2 (Honest-signing discipline, HSD).** An honest user `i` signs **only**:

- (h1) tree transactions and its initial commitment of an epoch `Ep`, after verifying `WF(Ep)` and possession of the full exit package (Spec [B-11], [B-12], [B-16]);
- (h2) leaf-channel state updates per the update protocol (Spec [B-24]), revoking each superseded state only upon holding the counterparty commitment for the new state;
- (h3) a forfeit `fft_i`, only while holding a fully verified package for the successor epoch (Spec [B-14]);
- (h4) cooperative closes it initiates or accepts.

The honest operator signs the mirror set, plus `E` only after all forfeits of stage 5 are in hand (Spec [B-15]), and follows the watch rule (h5): while a forfeited leaf's epoch is unexpired, upon confirmation of that leaf's parent, broadcast `fft_i` with CPFP (Spec [B-35]) — this is Spec A7, used *only* in T4.

**Definition 5.3 (Honest exit strategy `π_exit(i, Ep)`).** At some height `h₀`: broadcast the root-to-`L_i` path transactions sequentially, CPFP-ing each anchor at `f*`; after `L_i`'s parent confirms, wait `Δ_leaf`, broadcast `C_i(latest_i)` with CPFP; after it confirms, wait `Δ_rev`, spend `to_i` with CPFP; watch throughout, and if a revoked counterparty commitment confirms instead, spend its `Rev`-path within `Δ_rev`.

## 6. Spend enumeration and exclusivity

Throughout, fix a `WF` epoch `Ep` with honest `i ∈ S`, and work in an arbitrary execution.

**Lemma L1 (Exhaustive spend enumeration).** Every confirmed spend of every `Ep`-descended output is of exactly one of the following forms:

| Output | Possible confirmed spends before `H_exp` | At/after `H_exp` additionally |
|---|---|---|
| `O(E)`, tree node `o_j` | the unique pre-signed child transaction(s) of `T`; a fresh `Agg(S_j ∪{O})`-signed transaction that **every** honest member of `S_j` signed outside (h1)–(h4) — impossible under HSD | operator sweep via `CLTV` path |
| leaf `L_i` | some commitment `C_p(σ)` (≥ `Δ_leaf` after parent), `p ∈ {i,O}`, σ signed in (h1)/(h2); a forfeit `fft_i` if signed in (h3); a cooperative close signed in (h4) | operator sweep |
| `conn_i` | `fft_i`; any `Key(P_O)` spend (operator unilateral — constrained only by Spec [B-34], a policy rule; see T3, which does not rely on connector persistence) | — |
| `to_p` of `C_p(σ)` | `Key(P_p)` after `Δ_rev`; counterparty `Rev`-path iff σ revoked | — |
| `to_other`, anchors | their key owners | — |

*Proof.* Each row is by case analysis on `cond` (Def. 4.2(1), 4.3). Key-path spends require an `Agg` signature; by AX-SIG + Corollary 2.1, such a signature exists only on messages every honest member signed; by HSD those messages are exactly the listed pre-signed transactions. Script-path spends require the `CLTV`/`CSV`/`Rev` side conditions shown. The delay column entries follow from Def. 4.2(4) (`seq = Δ_leaf` on commitments, `⊤` on forfeits) and Def. 4.3 (`CSV(Δ_rev)`). No other condition branch exists. ∎

**Theorem T1 (Exclusivity — the path cannot be pre-empted).** In every execution, for every height `h < H_exp`: the only transactions that can confirm spending an output on the root-to-`L_i` path are the pre-signed path transactions themselves and, at the leaf, the objects `i` itself signed under HSD (its commitments; a forfeit iff `i` refreshed; a cooperative close iff `i` agreed).

*Proof.* Immediate from L1 rows 1–2, since `i ∈ S_j` for every path node (WF, Def. 4.2(2)) and `i` is honest: any non-enumerated spend would need a signature on a message `i` never signed, contradicting AX-SIG/Corollary 2.1. ∎

*Remark (F1 discharged formally).* T1 is precisely the property whose absence was v0.1's fatal flaw: no operator, federation, or user coalition excluding `i` has any spend capability on `i`'s path before expiry.

## 7. Main theorems

### T2 — Achievability of unilateral exit (Spec G1)

**Theorem T2.** Let `i` be honest with a verified exit package for `WF` epoch `Ep`, `E` confirmed `k`-deep, and let `i` run `π_exit` from height `h₀`. If no forfeit signed by `i` for `L_i` exists (i.e. `Ep` is `i`'s latest epoch), then by height

```text
h₀ + T_exit,   T_exit := depth·T_conf + Δ_leaf + T_conf + Δ_rev + T_conf
```

provided `h₀ + T_exit < H_exp`, there is a `k`-permanent output whose condition only `i` satisfies, carrying `≥ R_settled(i)` USDT (conditionally on AX-VS) and its `to_i` satoshis. No cooperation from any party is used.

*Proof.* By induction on the path. *Step d (unroll):* when the `(d−1)`-th path transaction is `k`-deep, the `d`-th has all inputs in `utxo`, no unsatisfied timelock (`seq = ⊤`, Def. 4.2(4)), a valid witness (WF, Def. 4.2(3)) and an `i`-spendable anchor (Def. 4.2(6)); by T1 nothing else can spend its input before `H_exp`; by AX-CONF it confirms within `T_conf`. After `depth·T_conf`, `L_i`'s parent is confirmed. *Leaf:* after `Δ_leaf`, `C_i(latest_i)` is consensus-valid; conflicts are, by L1: (a) other commitments — the operator's copy of `latest_i` yields the same `u(latest_i)` to `i` (Def. 4.3, symmetric amounts), and any *revoked* commitment that confirms is punished by `π_exit`'s watch clause within `Δ_rev`, yielding `ℓ(i) ≥ R_settled(i)`; (b) a forfeit — excluded by hypothesis; (c) a cooperative close — requires `i`'s fresh signature (h4), not given. So within `T_conf` a commitment resolving to `≥ u(latest_i)` for `i` confirms. *Claim:* after `Δ_rev`, the `to_i` spend (or `Rev`-path spend) confirms within `T_conf` (AX-CONF; the only competing branch, the counterparty `Rev`-path, requires `latest_i` to be revoked — false by Def. 4.3 of `latest`). Permanence after `k` more blocks is within `B ≥ k` of (M-bound). *USDT:* the package's consignment (WF, Def. 4.2(5); AX-VS VS-1..VS-3, VS-4 for the leaf state) now has its full witness chain confirmed, so by AX-RGB the allocation `u(latest_i)` on `i`'s output is valid and `i`-owned. ∎

**Corollary T2.1 (Deadline sufficiency; Spec §14.4).** If `h₀ ≤ D_exit = H_exp − M` then by (M-bound) `h₀ + T_exit + k ≤ H_exp − B + k ≤ H_exp`, with slack `B − k` absorbing scheduling; in particular every path transaction and the commitment confirm strictly before `H_exp`, so no `CLTV(H_exp)` sweep branch is ever available on any output `π_exit` spends. ∎

### T3 — Refresh atomicity (Spec §13, §8.2)

**Theorem T3.** Let honest `i` hold a claim in epoch `N` and engage in a refresh into `N+1` under HSD. In **every** execution and at every height `h < H_exp^N`, at least one of the following holds:

- (old) no `i`-signed forfeit of `L_i^N` can ever confirm, and T2's hypotheses hold for epoch `N`;
- (new) `E_{N+1}` is confirmed and T2's hypotheses hold for epoch `N+1`.

*Proof.* Case 1: `i` has not signed `fft_i`. Then by AX-SIG no valid forfeit exists (its leaf input needs `Agg({i,O})` on that message), and (old) holds — `Ep_N` was verified at its own ceremony (h1). Case 2: `i` signed `fft_i`. By (h3), at signing time `i` already held a fully verified package for `N+1`, whose tree signatures are complete (Def. 4.2(3)); note the package's validity is independent of any later adversary action, by T1 applied to `N+1` once `E_{N+1}` confirms. Sub-case 2a: `E_{N+1}` confirms (`k`-deep) — then (new) holds. Sub-case 2b: `E_{N+1}` never confirms — then `conn_i(E_{N+1})` never enters `utxo`, so `fft_i` (which spends it, Def. 4.4) can never confirm, and (old) holds. Sub-case 2c: a transaction conflicting with `E_{N+1}` becomes `k`-permanent — as 2b, permanently. There are no other cases. ∎

*Remark.* T3 is the formal statement that the ceremony ordering (Spec [B-11]/[B-14]/[B-15]) admits **no interleaving** in which an honest user has surrendered the old claim without holding an enforceable new one — the "atomicity" promised informally in Spec §18.3.

### T4 — Rollback unprofitability (Spec G3)

**Theorem T4.** Assume additionally the operator watch rule (h5) (Spec A7). Let adversarial user `j` hold a forfeited (superseded) leaf `L_j^N` in an unexpired epoch. Then in every execution: (i) every honest user's claims (any epoch) are unaffected by anything `j` broadcasts; (ii) `j`'s net proceeds from `Ep_N`-descended outputs are `0` minus fees paid.

*Proof.* (i) By L1, every transaction available to `j` spends only outputs on `j`'s own path, `j`'s leaf descendants, or anchors; disjoint subtrees share no outpoints, and shared-prefix broadcasts are exactly the pre-signed transactions honest users themselves rely on (helping, not harming, their T2 runs). (ii) For `j` to realize value it must confirm some `C_p(σ)` on `L_j^N` (L1 row 2; a cooperative close needs the honest operator's fresh signature, refused). Any commitment is invalid for `Δ_leaf` blocks after `L_j`'s parent confirms (Def. 4.2(4)); within that window the operator's `fft_j` — valid immediately, `seq = ⊤`, connector confirmed since `E_{N+1}` is (T3 case 2a is the only case where `j` is "forfeited") — is broadcast by (h5) and confirms by AX-CONF (`Δ_leaf ≥ T_conf` by Spec §19 constraints). `fft_j` pays everything to the operator (Def. 4.4). `j` paid unroll and CPFP fees. If the operator violates (h5), only the operator's own funds are lost — no honest-user quantity in any statement above depends on (h5). ∎

### T5 — Conservation and structural non-inflation (Spec G2)

**Theorem T5.** (i) Within a `WF` epoch, `Σ_{i∈S} ℓ(i) = a` and every reachable USDT disposition of the epoch (per T6) distributes exactly `a`. (ii) Across epochs, `Σ_{active Ep} a(Ep) ≤ Q_op ≤ Q`, where `Q_op` is the operator's reserve-descended holdings. (iii) Every cohort member verifies (i) and the root's consignment before signing anything; hence no epoch violating (i)–(ii) ever acquires an honest signature, and by AX-SIG none becomes enforceable against any honest participant.

*Proof.* (i) Induction over `T`: each transition conserves (AX-RGB/AX-VS, Def. 4.2(5)); leaves partition the root allocation. (ii) By Lemma 3.2 no allocation is consumed twice; distinct epochs consume disjoint reserve allocations, all descended from genesis with conservation at every step, bounding the sum by the operator's holdings and by `Q`. (iii) is HSD (h1) + checks V3–V4 ≡ Def. 4.2(5). ∎

### T6 — Outcome completeness: no unexpected reachable outcomes

Define the *intended outcome set* for a `WF` epoch `Ep`:

```text
O* = { Exit(i, σ)      — i receives u(σ), operator ω(σ), for some signed state σ;
                         σ ≠ latest_i is reachable only when σ is revoked and the
                         wronged counterparty declined or missed its Δ_rev penalty
                         window (Penalty was available throughout it)     (i ∈ S)
     ; Penalty(p→q)    — q receives all of ℓ(i) after p published a revoked state
     ; Forfeit(i)      — operator receives ℓ(i) of a refreshed leaf
     ; Coop(i)         — mutually signed distribution of ℓ(i)
     ; Sweep           — operator receives, at/after H_exp, everything unclaimed
     ; Fees            — anchor values and fees consumed by confirmation }
```

**Theorem T6.** In every execution — under arbitrary adversarial scheduling, arbitrary corrupt subsets, and arbitrary broadcast choices — every terminal disposition of every satoshi and every USDT unit committed to `Ep` lies in `O*`. In particular: there is no reachable state in which value is permanently stranded in a non-`O*` disposition, no third output class exists, and no party ever holds an enforceable claim not enumerated in `O*`.

*Proof.* By induction over the spend DAG rooted at `O(E)` (plus connectors), using L1 as the exhaustive case split at every output. Root and internal nodes: the only pre-expiry spends are the pre-signed child transactions (whose outputs recurse) and, at/after `H_exp`, the sweep branch → `Sweep`. Leaves: the four L1 cases map to `Exit`/`Penalty` (commitments: the confirmed one is either `latest_i` — `Exit(i, latest_i)` — or revoked, and the revoked case resolves within its `Δ_rev` window to `Penalty` if the counterparty acts, else to `Exit(i, σ)` with σ revoked — both dispositions are in `O*` as defined), `Forfeit`, `Coop`, or `Sweep`. Commitment outputs: L1 row 4 → the same dispositions. Connectors: `Forfeit` or operator key spend (`Fees`/operator funds). Anchors: `Fees`. USDT follows the same DAG by AX-RGB/AX-VS: every allocation is bound to one of these outpoints and conserved along it (T5), so its terminal owner is the terminal owner of the corresponding branch. Termination: every unspent `Ep`-output at `H_exp` acquires the always-available sweep branch, and the chain grows unboundedly (AX-FIN/AX-CONF), so no output remains forever in limbo *with an interested party*: for each output either some party is entitled and can force a spend (T2 machinery pre-expiry; sweep post-expiry), or no party ever spends it — and an eternally-unspent output is value the *operator* alone declines to sweep, which is `Sweep` deferred, not a new disposition. Exhaustiveness of the case split is L1; hence no execution step can create a disposition outside `O*`. ∎

*Remark (interpretation).* T6 is the formal content of "the specification has no unexpected irrelevant behaviors": the protocol's reachable outcome space is closed — six dispositions, each intended, each attributed — and adversarial creativity cannot enlarge it. Combined with T1–T4, *which* disposition occurs is also constrained exactly as the Spec's guarantees state.

### T7 — Credit bounds (Spec G4)

**Theorem T7.** Under HSD and the Spec's update rules ([B-26]–[B-29], formalized: sends complete a leaf-state decrease before the economic balance decreases; receives raise `u` at most to `ℓ(i)`; excess is `pending`), the quantity `pending_i = R_current,i − R_settled,i` satisfies:

- **(safety, everywhere)** `pending_i ≥ 0` at every reachable state, including mid-session states — the operator never over-settles;
- **(cap, at rest)** `pending_i ≤ P_max` at every *quiescent* state (no update session or HTLC of `i` in flight); a mid-send state may transiently show `pending_i ≤ P_max + x` for an in-flight send of `x`, which is `i`'s own outgoing value, not operator credit;
- **(global)** `Σ_i pending_i ≤ X_global` over quiescent states when the operator enforces its cap.

*Proof.* Induction over event types, base case `pending_i = 0` (Spec §14.2 sets `u = R_current` at the quiescent snapshot; well-defined by [B-30]/[B-31]). *Send of `x`:* the completed decrease lowers `u` by `x` first (so `pending` transiently rises by `x`, all of it the user's own departing value), then `R_current` falls by `x` on HTLC resolution — net effect on `pending` is `0`, and `u ≤ R_current` holds at both instants since the decrease is checked against the post-send balance ([B-26]). If the HTLC fails, a raise restores `u` (capped by [B-05]), returning to the prior quiescent state. *Receive of `x`:* `R_current` rises by `x`; [B-27] raises `u` by `min(x, ℓ(i) − u)` (net `pending` increase `max(0, x − headroom)`), and [B-29] forbids accepting a receive whose quiescent result would exceed `P_max`. *Raise/refresh:* `u` rises toward `R_current`, `pending` falls, floored at `0` by the [B-05] cap on raises. No event decreases `u` without an equal completed-pair `R_current` decrease, so (safety) is preserved by every step; (cap) holds at every quiescent state by the receive guard; (global) is the operator summing the same induction. ∎

### T8 — Expiry-bounded operator capability (Spec G5)

**Theorem T8.** Before `H_exp`, the operator's total unilateral capability over `Ep`-descended outputs is: spending connectors, anchors, `to_operator` outputs of confirmed commitments, `Rev`-paths of revoked states published by the counterparty, and forfeits of refreshed leaves. In particular the operator has **no** unilateral capability whatsoever over any output on an unrefreshed honest user's path. At/after `H_exp` it additionally gains exactly the sweep branches.

*Proof.* Read off L1: every other spend requires an `Agg` containing an honest user, hence (AX-SIG, HSD) one of the enumerated pre-signed or cooperatively signed objects. The `CLTV` branch is consensus-gated (Def. 1.3), not policy-gated. ∎

## 8. Realizability propositions

Achievability is not only about exits: the protocol must be *constructible* and its cooperative operations must terminate. Both are provable without any trust assumptions beyond participation.

**Proposition P1 (Epoch constructibility).** For every cohort `S` with `|S| ≤ N_max` and every allocation vector `ℓ : S → ℕ` with `ℓ(i) ≥ R_min` and `Σ ℓ(i) ≤ Q_op`, there exists a `WF` epoch realizing `ℓ`, and it is constructed and fully signed in `O(|S|·log_r |S|)` MuSig2 sessions, each user participating in `O(log_r |S|)` of them plus one leaf session.

*Proof (constructive).* Build the balanced `r`-ary tree over `|S|` leaves (exists for any `|S| ≥ 1`; depth `⌈log_r |S|⌉`). Assign conditions per Def. 4.2(1) — key aggregation is total (BIP-327 KeyAgg is defined for any finite key set). Fix `E` unsigned; SegWit txid-stability (Def. 1.1) makes all tree inputs well-defined pre-signing. Values: leaves get `btc_leaf`, nodes the recursive sums plus anchor budget — all standard by parameter choice (Spec [B-23]). RGB: allocate `ℓ` along the tree by splitting at each node (AX-VS VS-3 provides constructibility of the consignments). Sessions: one per tree node (its `S_j ∪ {O}` aggregate) — `Σ_d r^d ≤ (r·|S|−1)/(r−1) = O(|S|)` nodes, but each user appears in `depth` node sessions, giving the per-user and total bounds; each session terminates in two BIP-327 rounds among live participants. A participant failure aborts and restarts with `S' ⊊ S` (Spec [B-10]/[B-13]); since `S` is finite this terminates with the live sub-cohort. ∎

**Proposition P2 (Cooperative liveness).** Between an honest user and an honest operator, each of the following completes in a bounded number of message rounds, with no chain interaction: leaf-state raise/decrease (2 commitment exchanges + 2 revocations); quiescence for a snapshot (bounded by in-flight HTLC resolution, which BOLT semantics bound by the HTLC CLTV deltas); refresh (P1's ceremony + one forfeit signature + one broadcast); cooperative close (one transaction, two signatures). Consequently every value-flow of Spec §9.2 is realizable. ∎

*Proof.* Each is a finite, acyclic message protocol among two honest parties; the only unbounded ingredient, HTLC resolution, is bounded by the timeout heights carried by the HTLCs themselves. ∎

## 9. What is not proven

For audit honesty, the exact residue outside the theorems:

1. **AX-VS (Spec R-1).** All USDT-level conclusions (the asset halves of T2, T5, T6) are conditional on a virtual-seal instantiation satisfying VS-1..VS-4. The BTC-skeleton halves of every theorem are unconditional. This is the protocol's declared launch blocker; nothing here hides it.
2. **AX-CONF's constants.** `(f*, T_conf)` are empirical; T2/T4 degrade exactly as AX-CONF does (Spec §17.6, [B-47]). The *shape* of the degradation (delay, never theft, until the (M-bound) budget is exhausted) is what T2.1 proves.
3. **A7 scope.** T4(ii) needs the operator watch; T4(i) and all user-safety theorems do not. The Spec's claim that A7 and the disappearance scenario never overlap is T3: with no successor epoch, case 1 applies and no forfeit against the user's latest state exists.
4. **Cryptographic axioms.** AX-SIG is MuSig2/Schnorr security, assumed not proven here.
5. **Overlay-layer internals.** HTLC-level Lightning security (BOLT machinery) is imported, not re-proven; T7 interfaces with it only through the snapshot rule.
6. **Side channels.** Privacy (Spec §22) is disclosed, not modeled.
7. **Full-cohort rollover (Spec §9.4, [B-62]).** No new axiom is needed: the rollover signature over `O_N` is governed by the same discipline as (h3), so T3's case analysis carries over with the connector's role played by the `O_N` input itself — `E_{N+1}` confirming both destroys every old claim (their root input is spent, AX-FIN) and activates every new one, in a single transaction; `E_{N+1}` not confirming leaves `O_N` unspent and every old claim intact. T4 is vacuous for a rolled transition (no stale objects survive it). What is *not* re-proven: the ceremony-transport requirement that all of `S_N` sign, which is a liveness precondition, not a safety one — its failure falls back to §8–§9, already covered. The same single-transaction argument covers **atomic onboarding** (Spec §9.5, [B-63]): the depositor's input signature authorizes exactly `E_N` (Def. 1.3, sighash binding), so either `E_N` confirms — creating deposit consumption and leaf claim in one transaction — or the contributed UTXO remains the depositor's (AX-FIN); no interleaving yields a consumed deposit without an enforceable claim, and the contributed allocation enters T5's conservation accounting as an ordinary root-transition input.
8. **Committee mode (Spec §21.2).** The optional parked-leaf variant replaces the user's membership in path aggregates with an axiom **AX-CMT** (existential honesty: at least one member of the committee `C` never signs a spend of committee-covered outputs other than ceremony trees and conforming roll-forwards). Under the substitution, T1 and T2 hold for parked leaves verbatim with AX-CMT discharging the exclusivity step in place of the user's own HSD, and the direct `Key(U_i)` leaf path removes the commitment/`Δ_rev` stages from T2's bound. T3 and T4 are vacuous for parked leaves: no forfeits and no revocable states exist, and old/new claim uniqueness is immediate from AX-FIN because a roll-forward is a single transaction spending the old cohort root. The resulting guarantee G1′ is exactly G1 with AX-CMT added to its axiom set. AX-CMT itself is unverifiable by construction (non-signing cannot be proven) and nothing about committee behavior is proven here.
9. **Float invariant I4 (Spec §6.5, [B-67]).** Deliberately outside the theorems: coverage of `pending` by unencumbered operator float cannot be enforced by the protocol's cryptography — it is the content of NG1 — so it is stated as a conformance-and-disclosure rule. What *is* theorem-backed about pending remains T7 (its magnitude bounds) and the atomicity of its creation (one-preimage HTLC pairing, an overlay-spec/BOLT fact imported per §9 item 5, not re-proven here).
10. **Atomic mirrors (Spec §11.8, [B-68]/[B-69]/[B-70]).** Where offered, L1's leaf-commitment row gains two output classes — receive mirror `(U_i + preimage) ∨ (P_O after Δ_htlc) ∨ revocation` and its symmetric send mirror `(P_O + preimage) ∨ (U_i after Δ_htlc) ∨ revocation` — all paths relative-locked, so the case analysis stays exhaustive and Def. 4.2(4)'s no-absolute-timelock discipline is preserved. T6's outcome set is unchanged in kind: each mirror resolves to `Exit` at the effective post-payment split (the preimage holder claims immediately upon commitment confirmation, strictly ahead of the counterparty's `Δ_htlc` window), to `Exit` at the pre-payment split (counterparty reclaims an unactivated mirror after `Δ_htlc`), or to `Penalty` (revoked state published). T2 extends symmetrically to whichever party holds the preimage entitlement, adding no new assumption; T7's safety leg strengthens under send mirrors (the sender is never transiently under-settled, since the decrease is conditional on the payment's outcome). The atomic internal transfer composes legs on one preimage — its all-or-nothing property is exactly the single-secret pairing already imported as a BOLT-level fact (item 5), applied to three legs instead of two, and is not re-proven here.
11. **BTC profile (Spec Appendix B).** With sats as the settled asset, AX-RGB and AX-VS drop out of every theorem's axiom set: leaf values are enforced by transaction validity, so T5's conservation is immediate from AX-FIN, and the asset halves of T2/T6 coincide with their BTC halves. All results in this document then hold unconditionally on AX-FIN, AX-CONF, and AX-SIG (plus AX-CMT only where committee mode is used). The vBTC overlay does not appear in any theorem — it lives entirely inside the `R_current` bookkeeping of T7.

No other gaps are known to the authors; an auditor finding a reachable state not covered by L1's case analysis, or an outcome outside `O*`, refutes T6 and should be reported as a specification-level vulnerability (see README, Responsible disclosure).
